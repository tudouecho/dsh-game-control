# dsh-game-control v0.3 开发提示词

> 用途：把本文件完整交给编码 agent，即可在现有 `D:\dsh-chajian` 仓库实现 v0.3。
> 目标场景：让 agent 用 `game_control` 工具自动完成《Keep on Mining!》的完整挖矿循环。

---

## 0. 任务

在现有仓库 `D:\dsh-chajian` 中，为 `dsh-game-control` 插件（当前 v0.2.0）实现 v0.3。完成后，agent 应能用 `game_control` 工具完成以下流程：

1. 定位并**激活游戏窗口**（当前游戏窗口在后台，插件的键鼠动作只影响前台窗口）；
2. 点击「开始游戏」；
3. 等待约 2 秒，**识别**并点击右下角出现的「开始挖矿」按钮；
4. 在挖矿界面让鼠标以**窗口内大圆形轨迹**连续移动约 30 秒（直径约为窗口宽度的一半，约 2～3 秒一圈）；
5. 识别屏幕中间的「挖矿已完成」面板，点击「开始挖矿！」进入下一轮；
6. 可重复以上循环，可随时中止。

**必须保持 v0.2 全部 18 个动作、错误码、HTTP 路由、侧栏面板、日志和测试不回归。**

## 2. 现状与阻塞点（必须在 v0.3 解决）

- 鼠标只有**直线**动作：`mouse_move` 最长 5000ms，`mouse_drag` 也是直线，最多 200 步；**没有圆弧/曲线/循环轨迹**。
- Host 单动作超时：默认 15s；`screenshot`/`capture_window` 30s；`mouse_drag` 为 15s + duration。30 秒的圆形动作会被默认超时杀掉。
- Python worker 是**单请求串行**、动作全同步；没有后台任务/进度/取消模型。
- **没有窗口激活/前置动作**；工具只影响当前聚焦窗口。实测游戏窗口 `foreground=false`，直接点击会点到 DSH。
- 没有 `wait`、没有模板匹配/OCR/像素判定，无法在动作内等待并判断「按钮出现」「挖矿已完成」。
- 没有宏/循环机制，多轮游戏只能由模型一次次调用，效率低且容易出错。

## 4. 新增动作规格（字段名必须逐字一致）

### 4.1 `activate_window`（P0）

把目标窗口恢复并切到前台，供后续键鼠输入使用。

参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `window` | string | 与 `hwnd` 二选一 | 标题子串，大小写不敏感，选择规则同 `capture_window` |
| `hwnd` | number | 与 `window` 二选一 | 窗口句柄（优先） |
| `restore` | boolean | 否 | 默认 `true`：最小化时先 `ShowWindow(SW_RESTORE)` |
| `timeoutMs` | number | 否 | 默认 2000，范围 100–5000；等待变前台/取消最小化的超时 |

行为：

1. 用现有 `resolve_window()` 解析窗口；找不到 → `WINDOW_NOT_FOUND`。
2. 若最小化且 `restore`：`ShowWindow(SW_RESTORE)`，等待其退出最小化。
3. 依次尝试：
   - `SetForegroundWindow(hwnd)`；
   - 失败时用 `AttachThreadInput`（当前线程/前台窗口线程）后 `BringWindowToTop` + `SetForegroundWindow`，再 detach；
   - 仍失败时用 SendInput 轻点一下 `VK_MENU`（不产生字符）作为 Windows 前台锁的解锁技巧，再 `SetForegroundWindow`。
4. 最多等待 `timeoutMs`，轮询 `GetForegroundWindow()`；最终不是目标窗口 → `WINDOW_ACTIVATION_FAILED`（hint：窗口可能被 UAC/提权保护、属于其他桌面会话，或需用户手动点击一次）。
5. **不得注入点击**。

返回：

```json
{
  "window": {
    "hwnd": 18089860,
    "title": "Keep on Mining!",
    "class": "UnityWndClass",
    "pid": 11292,
    "process": "Keep on Mining!.exe",
    "rect": { "x": 959, "y": 512, "width": 1922, "height": 1126 },
    "clientRect": { "x": 969, "y": 553, "width": 1902, "height": 1080 }
  },
  "foreground": true,
  "attempts": 2
}
```

`clientRect` 是**客户区在虚拟桌面中的物理像素坐标**（`GetClientRect` + `ClientToScreen`），后续用于计算圆形中心/半径和点击位置。

### 4.2 `mouse_circle`（P0）

在指定屏幕上做**连续、平滑、定时**的圆形鼠标移动。

参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `centerX`, `centerY` | number | 是 | 圆心，屏幕物理像素（虚拟桌面坐标） |
| `radius` | number | 是 | 半径，像素，范围 1–5000 |
| `periodMs` | number | 否 | 一圈耗时，默认 2500，范围 300–20000 |
| `durationMs` | number | 否 | 总时长，默认 30000，范围 100–120000 |
| `direction` | enum | 否 | `"cw"`（默认，顺时针）/ `"ccw"`（逆时针） |
| `startAngleDeg` | number | 否 | 起始角，默认 `-90`（屏幕正上方 12 点钟方向）；0=右，90=下，180=左 |
| `samplesPerSecond` | number | 否 | 每秒注入次数，默认 120，范围 30–240（建议 ≥100 保证游戏轨迹平滑） |
| `leadInMs` | number | 否 | 开始画圆前从当前指针平滑移动到起点的时长，默认 300，范围 0–2000 |
| `button` | enum | 否 | `"none"`（默认）/ `"left"` / `"right"` / `"middle"`；非 none 时画圆期间按住，结束/异常时释放 |
| `abortKey` | string | 否 | 允许的键名即可，默认 `"f12"`；设为 `"none"` 禁用。画圆期间轮询 `GetAsyncKeyState`，按下即停止 |
| `hwnd` | number | 否 | 传入时校验该窗口在前台；画圆期间若前台窗口变化则自动停止（安全） |
| `dryRun` | boolean | 否 | 默认 `false`；`true` 时只计算轨迹和参数、**不注入任何输入**（供测试） |

语义与实现：

1. 校验：`radius/periodMs/durationMs` 范围合法；圆形包围盒必须完整落在虚拟桌面内，否则 `INVALID_ARGUMENT`（hint 提示调整 center/radius）。
2. 起始点：`θ0 = startAngleDeg * π / 180`；`x = centerX + radius * cos(θ)`，`y = centerY + radius * sin(θ)`。
3. 屏幕坐标 y 向下，因此 `θ` 递增为顺时针；`cw` 用 `+2π * t / (periodMs/1000)`，`ccw` 取反。
4. `leadInMs > 0` 时先从当前指针位置线性插值到起始点（沿用 `mouse_move` 的插值/计时方式），然后开始画圆。
5. 用 `time.perf_counter()` + 绝对截止时间调度（不要用累加 `sleep`，避免漂移）。总采样数 `n = int(durationMs/1000 * samplesPerSecond) + 1`；第 i 个采样点按 `t = i / samplesPerSecond` 计算角度。每帧 `move_to(round(x), round(y))`（SendInput 绝对坐标，沿用现有 `_normalized_abs`）。
6. 每帧（或每 25ms）检查一次中止键；每 ~100ms 检查一次 `hwnd` 前台状态（若提供了 hwnd）。
7. `finally` 中释放 `button`（若按住），日志记录一次汇总（不要每帧写日志）。
8. `dryRun:true` 立即返回轨迹统计，不移动鼠标、不等待。
9. **Host 超时**（关键）：`timeoutFor('mouse_circle') = min(180000, 15000 + leadInMs + durationMs + 5000)`。否则 30 秒动作会被默认 15s 杀掉。
10. 如果实测 DSH 对单次工具调用存在外部硬超时（例如 <35s），再追加 P2 的后台任务模型（见 §10），不要在本期硬扛。

返回：

```json
{
  "centerX": 1920, "centerY": 1075,
  "radius": 480, "periodMs": 2500, "durationMs": 30000,
  "direction": "cw", "samples": 3601, "loops": 12.0,
  "start": { "x": 1920, "y": 595 },
  "end": { "x": 1919, "y": 595 },
  "actualDurationMs": 30012,
  "aborted": false,
  "abortReason": null
}
```

中止时仍返回 `ok:true`，`aborted:true`，`abortReason` 为 `"abort-key"` 或 `"foreground-changed"`。参数错误才抛/返回错误码。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `durationMs` | number | 是 | 等待毫秒，范围 0–600000 |

### 4.4 `find_image`（P1）

在当前屏幕的指定区域内做模板匹配，返回匹配中心坐标（屏幕物理像素）。

参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `template` | string | 是 | 模板图片路径（PNG/JPG，绝对路径或相对 `GAME_CONTROL_HOME/templates/`），文件存在、可解码、≤2MB、宽高 ≤1024 |
| `region` | object | 否 | 搜索区域 `{x,y,width,height}`（屏幕物理像素）；缺省为主屏 |
| `window` / `hwnd` | string / number | 否 | 可选：两者取其一，用窗口 `clientRect` 作为搜索区域 |
| `threshold` | number | 否 | 0–1，默认 0.85 |
| `scales` | number[] | 否 | 1–5 个缩放比例，默认 `[1.0]`；如窗口分辨率可能变化用 `[0.8,1.0,1.25]` |
| `grayscale` | boolean | 否 | 默认 `true` |
| `maxResults` | number | 否 | 默认 3，范围 1–20；做非极大值抑制 |
| `debugPath` | string | 否 | 可选：把搜索区域/匹配框画出来另存，便于排障 |

返回（**找不到不是错误**，`ok:true, found:false`）：

```json
{
  "found": true,
  "source": "screen",
  "searchRegion": { "x": 959, "y": 512, "width": 1922, "height": 1126 },
  "template": { "path": "...", "width": 320, "height": 88 },
  "matches": [
    { "x": 1610, "y": 1005, "width": 320, "height": 88,
      "center": { "x": 1770, "y": 1049 }, "score": 0.94, "scale": 1.0 }
  ],
  "elapsedMs": 87
}
```

实现建议（无 OpenCV）：

1. 用 `screenshot.capture()` 取区域 RGB 原始字节，Pillow 转 `Image`，numpy 转 float32 灰度。
2. 模板加载：`PIL.Image.open(...).convert("RGB")`；若带 alpha，把 alpha 作为权重掩膜（可选）。
3. 归一化互相关（NCC）：
   - 分子用 `numpy.fft` 的 FFT 互相关（`irfft2(rfft2(img) * conj(rfft2(template_padded)))`）；
   - 分母用积分图/`cumsum` 计算局部 `sum(I)`、`sum(I²)`，模板 `sum(T)`、`sum(T²)` 为常数；
   - 多尺度时先缩放到较小尺寸粗搜，取候选峰后再回到原图邻域精细比对，保证 4K 区域 + 300×80 模板总耗时 < 1s。
4. 非极大值抑制：按 score 降序，抑制中心距离小于 `max(8, min(tw,th)/4)` 的重复结果。
5. 找不到模板文件 → `TEMPLATE_NOT_FOUND`；图片损坏/过大 → `INVALID_TEMPLATE`；numpy 缺失 → `MISSING_DEPENDENCY`。
6. 只读动作，不注入输入、不激活窗口；窗口在后台时可配合 WGC 抓窗口（可选实现，不是必需）。

### 4.5 `wait_image`（P1）

轮询 `find_image`，直到匹配出现/消失或超时。用于「等右下角按钮出现」「等挖矿完成弹窗出现」。

参数：继承 `find_image` 的全部参数，另加：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `timeoutMs` | number | 否 | 默认 15000，范围 100–600000 |
| `intervalMs` | number | 否 | 轮询间隔，默认 250，范围 50–2000 |
| `mode` | enum | 否 | `"appear"`（默认）/ `"disappear"` |

返回：

```json
{
  "found": true,
  "timedOut": false,
  "match": { "x": 1660, "y": 1000, "width": 260, "height": 84,
             "center": { "x": 1790, "y": 1042 }, "score": 0.91, "scale": 1.0 },
  "attempts": 9,
  "elapsedMs": 2210
}
```

超时返回 `ok:true, found:false, timedOut:true`（不抛错，方便 agent 分支处理）。Host 超时：`min(620000, timeoutMs + 5000)`。

模板建议：从游戏实际画面裁剪按钮**文字区域**（不要整块带边框/悬停高亮的大按钮），阈值 0.82–0.88；同一个模板在窗口分辨率不变时可反复使用。

### 4.6 `list_windows` 增加 `clientRect`（P0）

在 `window_capture._window_info()` 中增加：

```json
"clientRect": { "x": 969, "y": 553, "width": 1902, "height": 1080 }
```

用 `GetClientRect` + `ClientToScreen(0,0)` 计算，物理像素、与现有 `rect` 同一坐标系。保持现有字段不变，向后兼容。`activate_window` 也复用该字段。

用途：把用户要求的「圆形直径为窗口的一半」换算成像素半径：
- 圆心 = `clientRect` 中心；
- 半径 = `round(clientRect.width / 4)`（直径 = 窗口宽度的一半）。

## 6. 安全、日志、错误码

1. **中止**：`mouse_circle` 轮询中止键（默认 F12）；中止、异常、前台变化都必须释放按下的鼠标键；不要留下按住状态。
2. **前台保护**：传入 `hwnd` 时，若画圆过程中 `GetForegroundWindow() != hwnd`，立即停止并记录 `abortReason:"foreground-changed"`，避免把鼠标移动到其他窗口上继续操作。
3. **无后台动作**：不要新增常驻线程/定时器；除 `mouse_circle` 执行期外不得主动注入输入。
4. **日志**：`mouse_circle` 开始/结束各一条（圆心、半径、周期、时长、实际时长、是否中止）；`find_image`/`wait_image` 记录模板、区域、耗时、匹配数，不要记录整屏内容；`actions.jsonl` 追加新动作，`wait` 只记 duration，不记敏感内容。
5. 新增错误码（加入 `game_control.py` 的 `ERROR_CODES`、README 错误码表）：
   - `WINDOW_ACTIVATION_FAILED`
   - `TEMPLATE_NOT_FOUND`
   - `INVALID_TEMPLATE`
   - （可选）`ABORTED_BY_USER`；若采用「中止=成功 + aborted 字段」则不需要。
6. 参数校验风格与现有 `P()` 一致；未知字段仍返回 `UNKNOWN_PARAM`。

## 7. 目标场景手工验收（实机，需用户在场同意）

前置：游戏《Keep on Mining!》已启动，窗口未最小化（允许在后台）。本机参考环境：主屏 3840×2160，游戏窗口约 1922×1126 @ (959,512)，`UnityWndClass`，进程 `Keep on Mining!.exe`；这些值必须动态读取，不得写死。

1. `list_windows`（`titleContains:"Keep on Mining"`）→ 找到窗口，返回 `hwnd` 与 `clientRect`。
2. `activate_window`（传 `hwnd`）→ 返回 `foreground:true`；游戏窗口成为前台。
3. 准备模板：用 `capture_window`（WGC，可在后台）或 `screenshot` 截取游戏画面，用 Pillow 裁出 4 个模板（建议只裁文字区域，避开鼠标悬停高亮）：
   - `start_game.png`（主菜单「开始游戏」按钮文字）；
   - `start_mining.png`（右下角「开始挖矿」按钮文字）；
   - `mining_done.png`（完成面板标题「挖矿已完成」或面板特征区域）；
   - `next_round.png`（完成弹窗中的「开始挖矿！」按钮文字）。
   保存到 `%USERPROFILE%\.dsh\game-control\templates\keep-on-mining\`。模板不提交仓库（或由用户决定）。
4. `find_image`（region=clientRect）定位「开始游戏」→ `mouse_click` 其 `center`。
5. `wait(2000)`。
6. `wait_image`（`start_mining.png`，region=clientRect 右下角，timeout 15000）→ `mouse_click` 其 `center`。
7. 计算：`cx = clientRect.x + clientRect.width/2`，`cy = clientRect.y + clientRect.height/2`，`radius = round(clientRect.width/4)`。
8. `mouse_circle`：`centerX=cx, centerY=cy, radius=..., periodMs=2500, durationMs=30000, direction="cw", samplesPerSecond=120, button="none", hwnd=<游戏hwnd>`；观察鼠标在游戏内连续画圆、无跳变、约 12 圈；约 30 秒后倒计时归零。
9. `wait_image`（`mining_done.png`，timeout 45000）→ 确认「挖矿已完成」出现；再 `find_image` 定位 `next_round.png` → `mouse_click` → `wait(1000)`，开始下一轮。
10. 重复第 7–9 步至少 2 轮；确认每轮都能进入下一轮、没有卡死。
11. 安全测试：第三轮启动 `mouse_circle` 后按 `F12`，动作应在 100ms 内停止、鼠标键释放、返回 `aborted:true`。
12. 收集证据：开始游戏前、挖矿中、完成面板、下一轮计时器四张截图；查看 `%USERPROFILE%\.dsh\game-control\logs\game-control.log` 与 `actions.jsonl`；确认 `mouse_circle` 实际时长≈请求时长。

**风险提示**：若游戏使用 DirectInput/Raw Input 或反作弊导致 SendInput 被忽略，先在一个安全位置做一次小范围 `mouse_move` 验证游戏内圆形光标是否跟随；不跟随则需另做输入后端（不在本提示词范围内）。若 DSH 对单次工具调用有外部硬超时，改用 §10 的后台任务模型。
